# ラクガキバトル

紙に描いた落書きをカメラで取り込み、解析してステータス・属性・技セット・こせいを生成。
できたオリジナルキャラで **「力・技・速さ」の三すくみ**（毎ターン1つ伏せて選ぶ・目押しなし・生成で有利不利が固定されない）の1対1バトルを戦う、展示向けの Web ゲーム。

設計ノート: https://claude.ai/code/artifact/7f3c4c10-9108-4d6a-888b-02bf1c82f8fa

> **大改修中（2026-09〜）**
> - バトルを **わざリール → 「力/技/速さ」三すくみ** に刷新済み（`わざリール`・`ルーレット構え`・`こんしん` は廃止）
> - 解析を **AI Vision（Google Gemini）** に。実装済み：Vite の `/api/analyze` ミドルウェア（`server/`）。
>   キー未設定・ネット断のときは**ローカルのピクセル解析にフォールバック**
> - まだ React + Vite。SvelteKit + Rails への移行は次フェーズ（`/api/analyze` の中身＝`server/` はそのまま移せる）

## 開発

```bash
npm install
cp .env.example .env.local   # GEMINI_API_KEY を入れると AI 解析が有効に（省略時はピクセル解析）
npm run dev      # 開発サーバー（http://localhost:5273 固定。5173 は別プロジェクト用）
npm run build    # 本番ビルド（tsc + vite build、dist/ に PWA 出力）
npm run preview  # ビルド結果をローカル配信（/api/analyze も動く）
npx vitest       # エンジンのテスト（解析・バトル・AI変換・相性）
```

### AI 解析（画像 → ステータス）

- 撮影/選択した画像を `/api/analyze` に送る → **Gemini が「絵の特徴」を構造化 JSON で返す**（数値は返さない）
  → 既存の `featuresToCharacter`（ピクセル解析と同じ下流）がキャラに変換
- キー取得：<https://aistudio.google.com/apikey>（無料）。`.env.local` に `GEMINI_API_KEY=AIza...`
- キー未設定・API エラー・レート超過・ネット断 → **`analyzeImageData`（ピクセル解析）にフォールバック**
- `GEMINI_API_KEY=mock`（または `RAKUGAKI_AI_MOCK=1`）で、画像を見ずに擬似特徴を返す（通しの動作確認用）
- モデルは `RAKUGAKI_AI_MODEL`（省略時 `gemini-2.5-flash`）

## 構成

```
src/
├─ engine/            UI非依存の純粋ロジック（Vitest対象）※SvelteKit移行後も TS のまま維持
│  ├─ analyze/        画像特徴 → キャラ生成（決定論的：同じ絵 → 同じキャラ）
│  │                  次フェーズ：ピクセル特徴抽出を AI Vision に差し替え（下流の toCharacter は不変）
│  ├─ moves/          約90の技データ（data.ts）＋ 絵の特徴タグでの割り振り（assign.ts）
│  │                  次フェーズ：力/技/速さ のカテゴリを付与
│  ├─ personalities/  こせい60種（data.ts: パッシブ＋専用アクティブ）＋ 絵でのマッチング（assign.ts）
│  ├─ battle/         ★次フェーズで刷新：わざリール（ring.ts）廃止 → 力/技/速さ 三すくみ（engine.ts）
│  ├─ attributes.ts   属性相性（火→木→水、雷・闇は状態異常特化）※damage計算内の乗算のみに縮小
│  ├─ status.ts       状態異常14種（やけど/しびれ/ぬれ/からまり/のろい/どく/こんらん/各種UP・DOWN/ひるみ）
│  ├─ growth.ts       バトル報酬（ステータス強化・属性技進化・新わざ習得）
│  └─ rng.ts          シード付き乱数・画像ハッシュ
├─ scenes/            タイトル / 撮影 / リビール / 相手選択 / バトル / 報酬 / 結果 / 図鑑
├─ store/             Zustand（画面遷移・キャラ・図鑑）
├─ data/              テスト用CPUロスター（雑なダミー4体）
└─ components/         手描きテイストのUI部品
```

### 次フェーズの構成（設計確定）

```
SvelteKit（Node 常駐）    フロント＋BFF。src/engine/（TS, Vitest）はここに残す
      │  fetch /api/analyze（multipart 画像）
      ▼
Rails API（--api）        「画像 → AI → 構造化特徴JSON」「ジョブ」「原画保存」「キャッシュ」専任
      ├─ SolidQueue        ジョブ（DBベース＝Redis不要）
      └─ Postgres          ジョブ状態・AI結果キャッシュ（画像ハッシュ）・原画メタ
```

- **AIの返すもの（数値は返させない）**：`{ attribute, features{0..1のスコア群}, tags[固定語彙], archetype_hint, name, flavor, reveal_notes[] }` → 既存 `toCharacter`/`assignMoves`/`assignKosei` が Character 化
- **品質**：構造化出力・語彙固定・**画像ハッシュでキャッシュ（同じ絵→同じキャラ）**・修復リトライ・**フォールバック＝既存ピクセル解析**（AI障害/ネット断）
- **リビール**：ジョブは特徴JSONを一度に返す。段階表示はクライアント演出（`queued/analyzing/mapping/done` の進捗）

## バトル（力・技・速さ の三すくみ）※設計確定・実装は次フェーズ

- **毎ターン、力・技・速さ を1つ 伏せて選ぶ**（両者同時 →「せーの！」で公開）
  - **サイクル：速さ → 力 → 技 → 速さ**
    - **速さ**（青）… 振りかぶる前に先手を取る。**力に勝つ**
    - **力**（赤）… 小細工ごとぶち抜く。**技に勝つ**
    - **技**（緑）… 見切ってカウンター。**速さに勝つ**
  - **色分け（力＝赤／技＝緑／速さ＝青）＋アイコン＋文字**の3点で表示。ボタンに「◯に強い／◯に弱い」を常時表示、1ターン目だけコーチ
  - **クラッシュは左右対称・ステータス無関係** ＝ **生成された絵で有利不利が固定されない**（勝敗は毎ターンの読み合いで決まる）
- **こせい** … その絵だけの専用スキル。**三すくみの外のワイルドカード**（CD／回数制）。発動はするがクラッシュに参加しない＝晒される（守り系こせいは例外）
- **こんしん**（検討）… HP35%以下で解禁の4つ目。ガード無視の特大、被弾で+50%。こんじょうで威力可変 ＝ 引いてる側の逆転レバー
- **絵の色の出し方**：技セット（5〜8）を **力／技／速さ** に振り分け＋各カテゴリに基本技を保証（へなちょこパンチ等）。**得意カテゴリに良い技が集まる ＝ 有利不利は固定されず「戦い方」だけが違う**（近距離キャラ vs 差し合いキャラ）。あいまいな絵は3カテゴリ均等＝器用貧乏という個性
- **一方的にしない**：こんじょう逆転（HP減で火力・状態成功率↑）／こんしん／**クラッシュ負け側に小さな慰め**（次ターン被ダメ減 or 小回復）／1発上限は相手最大HPの55%・クリ非連鎖／**サドンデス（12ターン〜）はリード側を多めに削る**非対称
- **三すくみを知らなくても「力！」連打で試合になる**（ゲートにしない・分かる人が得する層）
- ステータス6軸：HP・**こうげき**・**ぼうぎょ**・**すばやさ**・**きゅうしょ**（クリ率）・**こんじょう**（状態異常/回復/逆転）。damage 計算に使う。「型」の独立表示は廃止 → キットの偏りが個性
- 属性（火水木雷闇）：damage 計算内の乗算には残す（火→木→水 ×1.4／×0.8、雷・闇は状態異常特化）が、**「相性で勝負が決まる」構造にはしない**（生成固定を避けるため）
- 技は約90：共通＋属性3段階×5＋特殊＋治療・補助。**絵の特徴タグ**で 5〜8個 割り振り、**力/技/速さ のカテゴリを付与**。強い技はクールダウン
- 状態異常14種＋**治療手段**（技セットに必ず1つ治療系）
- ホットシート：伏せ選択のため端末を1回渡す「せーの！」。ソロは CPU が自動
- 報酬：ステータス強化／属性わざ進化／新わざ習得

### 現行コード（旧わざリール方式・次フェーズで撤去）

`src/engine/battle/`（`ring.ts` の `buildReel`/`spinReel`、`engine.ts` の `Stance 'roulette'`・`applyKoseiRoulette`）は**まだ旧方式**（縦スクロールのリールを「とめる！」・完全確率、毎ターン「せめる／ルーレット／こせい」）。三すくみ実装時に撤去。

## 展示運用（予定）

- 会場PCで SvelteKit をビルド・常駐、ブラウザを全画面 Kiosk モード。Rails API ＋ Postgres も会場PC（またはLAN内）で常駐。
- カメラは固定スタンド。**解析は AI 必須**なので会場の安定ネットが前提。ネット断のときだけ**ローカルのピクセル解析にフォールバック**（バトル・図鑑・報酬はネット無しでも動く）。
- 公開用は SvelteKit を Node ホスト（Railway / Fly 等）、Rails ＋ Postgres も同様。
